# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Two embeddable web toys for the MusKI website — a drum machine and a bass sequencer — driven by Google
Magenta RNN models. Not an npm library: it ships as a `<script>` + CSS bundle, and host pages embed it
with a `data-component` placeholder div. `README.md` holds the full consumer-facing `data-` attribute
reference (drum codes, preset format); don't duplicate it here.

## Commands

Node `>=18.19.0`. Only three npm scripts exist.

```bash
npm run build      # webpack --mode=production
npm run watch      # webpack --mode=development --watch
npx eslint src/js                      # no lint script exists; run the binaries directly
npx stylelint "src/sass/**/*.scss"
```

- **There are no tests.** `npm test` is the npm-init stub and exits 1. There is no CI. Verification is
  manual: build, serve, open a demo page, listen.
- **There is no dev server.** Serve the repo root over HTTP with any static server — `file://` fails
  because the app fetches checkpoints and samples over relative paths. Typical loop: `npm run watch` in
  one terminal, a static server on the repo root in another.
- Terser minification runs in **both** modes, so `--mode=development` output is still minified.
- Clear `.babel-cache/` when debugging Babel output (see the note at `webpack.config.js:27`).

## Build output is committed

`dist/` **and** the root `index.html` / `index-bass.html` are generated by webpack and tracked in git.
After changing anything in `src/`, run `npm run build` and commit the regenerated files alongside your
source change.

- Edit `src/html/index.html` / `src/html/index-bass.html` — **never** the root copies, which
  HtmlWebpackPlugin overwrites (minified) on every build.
- `CleanWebpackPlugin` wipes `dist/**/*` each build, so the whole directory turns over in the diff.
- Bundle filenames are version-stamped from `package.json`: `dist/muski-drums-<version>.{js,css}`.
  Bumping the version renames them and rewrites the `<script src>` in both HTML pages — that rename is
  the whole shape of a release commit.

## Architecture

```
main.js  (scans [data-component=muski-drums|muski-bass], reads data-* attrs)
  |
  +- MuskiDrumsManager       page-level singleton; owns the expensive shared resources
  |    +- initAi()      -> MuskiRnnDrums -> @magenta/music MusicRNN
  |    +- initSampler() -> Tone.Players (sample files named <midiPitch>.mp3)
  |    +- warmUpAI()    -> one throwaway continueSeq, to pay the TF.js shader-compile cost up front
  |    +- createToneTransport() -> MuskiToneTransportController (one per widget)
  |
  +- new MuskiDrums(ai|null, sampler, transportController, options)    one per matching div
       +- MuskiSequencer    the grid; canonical pattern state
       +- BarButton xN      generate / random / markov
       +- Tone.Sequence     16 steps @ '16n', .start(0)
```

`MuskiBassManager` / `MuskiBass` / `MuskiRnnBass` mirror this, with a `Tone.Synth` in place of
`Tone.Players`. Passing `null` for `ai` is how "AI disabled" is expressed.

- **jQuery is a required global `$`**, loaded from a CDN by the host page. It is never imported and
  never bundled (`.eslintrc.json` sets `env.jquery`). Bootstrap 5 classes are assumed present too.
- **State lives in the DOM.** A sequencer cell is on iff its button has class `on`;
  `sequencer.getSequence()` reads it back as `Array<Array<midiPitch>>` indexed by step. There is no
  store, reducer, or model object.
- **Modules talk over Node's `events`** — one `this.events` EventEmitter per object. `MuskiSequencer`
  emits `cell-on` / `cell-off` / `update`; the transport controller emits `start` / `stop`; `BarButton`
  emits `start` / `abort`; `MuskiDrums` emits `step` / `start` / `stop` as its outward-facing hook.
- **Transport arbitration**: `MuskiToneTransportManager` holds `activeController`, lazily calls
  `Tone.start()` to unlock autoplay, and stops the previous controller before starting the next. Every
  widget's `Tone.Sequence` is scheduled at time 0 permanently and no-ops unless it owns the transport.
- **AI generation** (`MuskiDrums.generateUsingAI`): the first `inputLen = 6` of `sequenceLen = 16` steps
  are the seed -> `buildNoteSequence` (`src/js/lib/note-seq.js`) -> `quantizeNoteSequence` ->
  `continueSeq` -> returned GM pitches normalized through `reverseDrumMap` then `drumMap` -> revealed
  column-by-column by `sequencerPatternTransition`. `inputLen` and `sequenceLen` are module constants,
  not options — changing the seed/output split means editing the component file.
- **Assets are fetched at runtime, not bundled**: `sounds/<kit>/<midiPitch>.mp3` and
  `checkpoints/<model>/`. Both directories are **gitignored**, so a fresh clone has neither and the
  demos 404 until you supply them or point `data-ai-checkpoint` / `data-soundfont` at
  `https://static.muski.io/...`. Only `vendor/font-awesome/*.svg` goes through webpack, via
  `asset/resource`, referenced from SCSS.

The programmatic handle on an instance is `$el.data('muski-drums', drums)`, stashed by `main.js` after
it replaces the placeholder.

## Conventions

- **Component pattern**: a class with `options` merged over a local `defaultOptions`, an `events`
  EventEmitter, a `$element` built imperatively with chained jQuery in the constructor, and
  `handleXxx()` methods bound as handlers. `MuskiSequencer`, `BarButton`, `HoldBarButton` all follow it.
- **ESLint extends `airbnb`.** The `comma-dangle` override requires trailing commas everywhere *except*
  function arguments — see the multi-line constructor calls in `src/js/main.js`. `no-console` allows
  only `warn` and `error`. The `globals` block in `.eslintrc.json` (`d3`, `projection`,
  `sampleEllipses`, …) is copy-paste leftover from an unrelated project; ignore it.
- **SCSS**: `src/sass/default.scss` is the only entry and uses modern `@use`. Partials are
  `_mod_<area>.scss`, and rules are nested under `.muski-drums` / `.muski-bass` to scope them.
- **i18n**: `src/js/i18n/{en,de,fr}.js` each export `{ ui, drums, notes }`. Adding a language means
  adding the file **and** registering it in *two* separate maps — `DefaultStrings` in `muski-drums.js`
  and `Strings` in `muski-bass.js`. Only the drums component accepts an `options.strings` override, and
  it is shallow-merged per language, so an override must supply whole `ui` / `drums` sub-objects.
- **Commits** use Conventional Commits (`feat:`, `fix:`, `chore:`), capitalized, ending with a period.

## Gotchas

- `data-ai-checkpoint` and `data-soundfont` are **not per-instance**. `main.js` reads them off the first
  matching element on the page (`src/js/main.js:21-22` and `:65`) and builds one manager, one model, and
  one sampler shared by every widget.
- **Two drum vocabularies.** `data-drums` takes `BD,SD,CH,OH,LT,MT,HT,CR,RD` (translated by `drumArgs`
  at the top of `main.js`), while `data-preset` and all internal code use
  `kick, snare, hihatClosed, …`. Internally rows are keyed by MIDI pitch **as a string**, hence the
  `String(row)` calls everywhere.
- Drums opt **in** to AI (`data-with-ai === true`), bass opts **out** (`!== false`) —
  `src/js/main.js:32` vs `:73`.
- The `ai-input` CSS class is applied to steps 6–15, i.e. the AI *output* region. The name is
  misleading; the seed region is steps 0–5.
- `src/js/muski-tone.js` is an empty stub and `src/js/lib/hold-bar-button.js` is currently unused.
- `dotenv-webpack` is wired up in `webpack.config.js`, but nothing in `src/` reads `process.env` and no
  `.env` exists. It is vestigial.
